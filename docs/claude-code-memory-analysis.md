## 1. Claude Code 双层记忆架构深度解析

### 1.1 整体架构概览

Claude Code 采用**清晰分离的双层记忆架构**：

```
┌─────────────────────────────────────────────────────────────┐
│                    用户会话 (User Session)                    │
├─────────────────────────────────────────────────────────────┤
│                     Session Memory                            │
│  • 会话内短期记忆                                            │
│  • 12K token 上限                                            │
│  • 每 5K tokens / 3 tool calls 触发自动压缩                  │
│  • 增量更新保持最新信息                                      │
└────────────┬──────────────────────────────────────────────────┘
             │
             ▼  触发条件满足时自动 consolidate
┌─────────────────────────────────────────────────────────────┐
│                     Auto Memory (持久化)                     │
│  • 跨会话长期记忆                                            │
│  • 按主题分文件存储                                          │
│  • 触发条件：                                                │
│    - 超过 24 小时                                           │
│    - 超过 5 个会话                                          │
│    - 获得写锁                                                │
│  • 自动后台整理：Orient → Gather → Consolidate → Prune      │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 Session Memory 设计细节

**核心参数：**
- 默认 token 上限：**12,288 tokens**
- 压缩触发阈值：
  - 每 **5,120 tokens** 生成压缩版本
  - 每 **3 次工具调用** 检查是否需要压缩
- 压缩策略：保留用户指令和关键结论，丢弃冗余交互

**压缩工作流：**
```
1. 检测 token 计数是否超过阈值
2. 调用 LLM 生成压缩摘要：
   - "Summarize the conversation so far, keep all key decisions, user preferences, and action items"
   - 保留重要的上下文，去除重复和无关内容
3. 用压缩摘要替换原始消息列表
4. 继续对话
```

**优点：**
- 保持会话上下文流畅
- 自动控制 token 数量不爆炸
- 用户体验无感知

### 1.3 Auto Memory 设计细节

**存储结构：**
```
memory/
├── memories/
│   ├── project-X.md
│   ├── user-preferences.md
│   ├── decisions-2026Q1.md
│   └── ...
└── index.json  # 主题索引
```

**触发条件（全部满足才触发）：**
1. ✅ 上一次 consolidation 超过 **24 小时**
2. ✅ 累积了 **5 个以上** 新会话
3. ✅ 成功获得**排他锁**（防止多实例并发）

**四阶段 consolidation 流程（Dream System）：**

| 阶段 | 动作 | 说明 |
|------|------|------|
| **Orient** | 分析自上次整理以来的新会话，识别关键信息、用户偏好、决策、待办 | 定位需要整理的内容 |
| **Gather** | 提取相关内容，按主题分组 | 收集信息 |
| **Consolidate** | 合并到对应记忆文件，去重、整合、结构化 | 整合写入 |
| **Prune** | 删除过时信息，清理冗余 | 保持记忆整洁 |

**关键特性：**
- **后台自动运行**，不阻塞用户交互
- **主题分文件**，容易检索和编辑
- **增量更新**，不会一次性重写所有内容
- **版本化**，可以回滚

### 1.4 触发条件设计精髓

```python
# Claude Code 触发逻辑伪代码
should_run = (
    hours_since_last_consolidation() > 24
    AND count_new_sessions_since_last() > 5
    AND try_acquire_lock()
)
# 频率控制：太频繁会浪费 token，太疏送记忆过时
```

**设计思想：** 
- 不每次对话都整理（节省 token）
- 批量处理效率更高
- 锁保证多实例部署安全

### 1.5 反蒸馏保护（Anti-Distillation）

Claude Code 在每次 API 请求中注入**虚假工具调用**毒化数据集：

```python
# 伪代码
if anti_distillation_enabled:
    for i in range(random.randint(1, 3)):
        fake_tool = random.choice(FAKE_TOOLS)
        messages.append(fake_tool_call(fake_tool))
        messages.append(fake_result(fake_tool))
```

目的：防止别人偷用 Claude Code 对话数据蒸馏克隆 Claude。这是业务保护措施，nanobot 作为开源项目不需要这个特性。

## 2. 当前 nanobot 记忆系统现状

### 2.1 当前架构

```
/root/.nanobot/workspace/memory/
├── MEMORY.md       # 长期事实（手动整理）
└── HISTORY.md      # 追加式事件日志
```

**核心特点：**
- `MEMORY.md`: 人工维护的长期事实，每次加载到上下文
- `HISTORY.md`: 所有事件追加日志，可搜索但不自动加载
- 会话内记忆：LLM 上下文窗口保存完整对话
- **无自动压缩**、**无自动 consolidation**

### 2.2 当前优缺点

| ✅ 优点 | ❌ 缺点 |
|---------|--------|
| 极简实现，理解容易 | 无自动压缩，长会话 token 容易爆炸 |
| 人工维护，信息准确 | 跨会话记忆需要手动整理 |
| 不浪费 token 做整理 | 用户体验差，重启会话后记忆丢失 |
| 无依赖 | 知识沉淀效率低 |

## 3. 技术对比

| 维度 | Claude Code 双层记忆 | 当前 nanobot | 差异 |
|------|---------------------|--------------|------|
| **架构** | Session Memory (短期) + Auto Memory (长期) 双层分离 | 单层人工维护 | Claude 自动化程度高很多 |
| **会话内压缩** | ✅ 自动，每 5K tokens/3 工具调用触发 | ❌ 无 | Claude 自动控制 token 用量 |
| **压缩策略** | ✅ LLM 智能压缩保留关键信息 | - | nanobot 长会话容易溢出 |
| **跨会话记忆** | ✅ 自动后台整理，按主题分文件 | ❌ 手动整理到 MEMORY.md | Claude 自动沉淀知识 |
| **触发条件** | ✅ 24h + 5会话 + 锁 → 平衡频率 | - | 从不自动触发 |
| **整理流程** | ✅ Orient → Gather → Consolidate → Prune 四阶段 | 手动 | Claude 全自动 |
| **存储格式** | ✅ 按主题分 Markdown 文件 + 索引 | 单文件 | 更好的组织，更容易编辑 |
| **token 治理** | ✅ 主动控制，不会超限 | 靠用户控制 | nanobot 容易超限 |
| **代码量** | ~500-800 行 | ~50 行 | Claude 更复杂但功能完整 |
| **并发安全** | ✅ 排他锁保护 | 单实例，不需要 | nanobot 当前不需要 |

## 5. 分阶段升级方案

### 5.1 P0 阶段（核心功能，1-2 天工作量）

**目标：实现 Session Memory 自动压缩**

```
任务：
1. 在 MemoryStore 添加 token 计数
2. 添加压缩触发阈值配置（可配置）
   - 默认：5000 tokens / 3 工具调用
3. 实现压缩函数：调用 LLM 压缩对话
4. 替换原始消息列表为压缩版本
5. 添加配置开关：features.compression = true/false

文件改动：
- nanobot/agent/memory.py → 新增压缩逻辑
- nanobot/config/schema.py → 添加压缩配置
- 新增：nanobot/agent/memory/compression.py
```

**收益：** 立刻解决长会话 token 溢出问题

### 5.2 P1 阶段（Auto Memory 基础，2-3 天工作量）

**目标：实现基础 Auto Memory 持久化**

```
任务：
1. 设计存储结构：memory/auto/{topic}.md
2. 实现触发条件检测：
   - 读取上次整理时间
   - 统计新会话语句数
3. 实现四阶段整理框架：
   - Orient: 分析新会话提取关键信息
   - Gather: 分组
   - Consolidate: 写入文件
   - Prune: 删除过时
4. 添加排他锁机制（文件锁）
5. 集成到心跳或后台任务

文件改动：
- 新增：nanobot/agent/memory/auto_consolidation.py
- 新增：nanobot/agent/memory/topic_index.py
- 修改：nanobot/agent/loop.py → 触发检测
- 修改：config/schema.py → 添加 auto_memory 配置
```

**收益：** 自动跨会话记忆沉淀

### 5.3 P2 阶段（优化体验，1 天工作量）

**目标：后台整理，不阻塞交互**

```
任务：
1. 将 consolidation 放到后台子 agent
2. 用户继续对话，整理完成后生效
3. 添加记忆搜索功能
   - 按关键词搜索相关记忆
   - 注入到上下文

文件改动：
- 修改：nanobot/agent/context_builder.py → 检索并注入相关记忆
- 新增：nanobot/agent/memory/search.py
```

### 5.4 P3 阶段（可选高级特性，1 天工作量）

**目标：**
- 记忆文件版本化（git 管理）
- 支持用户手动编辑记忆文件
- 过期记忆自动修剪
